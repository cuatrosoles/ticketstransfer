## Debug en emulador

1. **Metro** – En una terminal: `pnpm start` (desde `apps/mobile`).
2. **Ejecutar la app** – En otra terminal: `pnpm android` (compila, instala y conecta a Metro para hot reload).
3. **Dev Menu** – `Ctrl + M` (o `Cmd + M` en macOS) para:
   - Reload
   - Debug (Chrome DevTools)
   - Fast Refresh
   - Perf Monitor
4. **Logs** – `adb logcat *:S ReactNative:V ReactNativeJS:V` para ver logs en tiempo real.
5. **API local** – La API debe estar en marcha (`pnpm dev` en `apps/api`); el emulador usa `http://10.0.2.2:3001`.

Flujo típico: terminal 1 con `pnpm start`, terminal 2 con `pnpm android`, y la API corriendo en otra terminal.

## Cambios realizados

### 1. **Patch para react-native-biometrics** (`patches/react-native-biometrics+3.0.1.patch`)
- Se añade **BIOMETRIC_WEAK** como fallback además de BIOMETRIC_STRONG.
- En dispositivos con solo reconocimiento facial (Class 2), BIOMETRIC_STRONG falla; BIOMETRIC_WEAK permite usarlos.
- En Android 11+ (API 30+), se usan ambos tipos de biométricos.

### 2. **`allowDeviceCredentials: true`** en `secureStorage.ts`
- Permite usar PIN, patrón o contraseña del dispositivo si falla la biometría.
- Mejora la compatibilidad en dispositivos con biométricos limitados.

### 3. **Keychain en Android** con `BIOMETRY_CURRENT_SET_OR_DEVICE_PASSCODE`
- Sustituye `BIOMETRY_CURRENT_SET` por `BIOMETRY_CURRENT_SET_OR_DEVICE_PASSCODE`.
- Permite recuperar el token con biométricos o con PIN/patrón del dispositivo.
- Evita errores cuando el acceso solo biométrico falla en algunos dispositivos.

## Cómo probar

1. Recompilar la app:
```bash
cd v2/apps/mobile
pnpm android
```

2. Si ya tenías biométricos activados y ves problemas, cierra sesión, vuelve a iniciar sesión y activa de nuevo la biometría.

3. En el emulador Android, configura huella o reconocimiento facial en **Settings → Security → Fingerprint / Face unlock** antes de probar.
